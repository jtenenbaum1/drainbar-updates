DrainBar privacy policy

Last updated: September 9, 2026

DrainBar is a macOS menu bar utility for viewing coding-tool usage and reset times. DrainBar has no developer-operated backend, advertising, analytics SDK, or DrainBar account. The developer does not receive your usage history through the app.

Access on your Mac

The Mac App Store edition supports Codex local session metadata. You select the Codex data folder in a standard macOS folder picker. The grant is read-only and is remembered using a security-scoped bookmark. This edition does not read Codex or Claude account credentials and does not offer Claude account usage.

The direct-download edition can read sign-in credentials and usage metadata from existing Claude Code and Codex installations. It can also read Claude Code's existing Keychain item, subject to macOS access controls.

Local session logs can contain prompts, code, and conversation content. DrainBar reads log records to extract quota information and activity timing; it does not save or transmit the conversation content. It never modifies provider files or renews a provider sign-in. In the direct-download edition, tokens are used in memory and are not copied into DrainBar preferences or its history database.

Network requests

The Mac App Store edition has no outbound-network entitlement and makes no provider or service-status requests. Opening support, privacy, or provider links asks macOS to open the corresponding website in your browser.

When live usage is enabled in the direct-download edition, DrainBar sends authenticated requests to the relevant provider's usage service. These requests include the existing provider credential; Codex requests can include the provider account identifier. The service also receives ordinary connection information, such as your IP address and DrainBar's version. The direct-download edition also checks Anthropic and OpenAI service-status pages. Provider services process requests under their own privacy policies:

  • Anthropic privacy policy
  • OpenAI privacy policy

DrainBar does not send local session logs, prompts, code, or saved pacing history to these services. Sample mode does not start live usage, status, or history imports; in the direct-download edition, an already-running request may finish when sample mode is enabled, and its usage result is discarded.

The direct-download edition uses Sparkle to check for updates and download releases from GitHub when update checks are enabled or requested. GitHub receives ordinary download-request information. The Mac App Store edition uses Apple's update mechanism and does not include Sparkle.

Local storage and controls

Preferences and folder-access bookmarks remain on your Mac. Optional personalized pacing stores normalized usage percentages, reset timestamps, activity timing, and import checkpoints. Checkpoints use hashed source identifiers derived from file paths; raw conversation content and credentials are not stored in the history database.

History retention covers 28 completed days plus data needed for active quota cycles. Choose Settings → Refresh & Pacing → Clear History to remove the local history database contents. Turning personalized pacing off stops further history imports; it does not delete existing history. Preferences and saved folder grants persist separately. Sample data is illustrative and does not represent your account.

Support

Contact DrainBar support. Issues are public: do not post passwords, tokens, provider authentication files, session logs, or private conversations. If you voluntarily post information in an issue, GitHub and the developer can see it.
